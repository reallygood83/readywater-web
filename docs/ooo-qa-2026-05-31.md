# Readywater Web OOO QA

Date: 2026-05-31
Scope: `readywater-web` local WebUI, Gemini intent parser, Teachermall + i-Scream Mall search, budget kit generation.

## Executive Verdict

The app proves the technical path, but it does not yet feel like a satisfying AI shopping assistant. Gemini is currently used only to convert natural language into search JSON. After that, the system falls back to deterministic keyword search, a simple value-per-price budget algorithm, and template use-case sentences. This means users see real products, but they do not get enough reasoning, curation, lesson-fit explanation, or confidence that the selected basket is actually a good purchase plan.

Current user satisfaction estimate: 5/10.

Target for a teacher-facing prototype: 8/10.

## What Works

- Gemini API is connected and `/api/intent` returns `parser: gemini`.
- Product links are grounded in live Teachermall and i-Scream Mall URLs.
- Budget generation keeps total under the requested budget.
- Markdown export exists.
- The WebUI has a natural-language entry point, product images, prices, mall badges, and cart controls.

## Highest Priority Findings

### P0. AI is not yet doing the important recommendation work

Gemini only extracts intent fields like grade, budget, sort, and keywords. It does not rank retrieved products with educational reasoning, explain tradeoffs, remove weak candidates, or write a teacher-ready recommendation.

Evidence:

- `/api/intent` returns Gemini intent, then `buildBudgetKit()` uses simple keyword/value rules.
- `useCaseForProduct()` generates generic template sentences.

Impact:

- The UI says AI, but the result feels like a search page plus auto-cart.
- Teachers still need to decide which products are worth buying.

Recommended fix:

- Add a second Gemini step after product retrieval: `rankAndExplainProducts(prompt, candidates)`.
- Gemini should receive only real candidate product JSON and return structured rationale, lesson use cases, reject reasons, and recommended quantities.
- Keep prices and links immutable from mall APIs.

### P0. Search relevance has obvious false positives

The current sports filter accepts product names containing `조끼`, so `구명조끼`, `수영조끼`, and water-safety craft products appear in a 6th grade PE equipment search.

Evidence from test prompt:

- `구명조끼와 부력도구 입체 팝업 스티커 북`
- `구명조끼팝업북만들기`
- `생존수영 폰토스 수영조끼`

Impact:

- Trust drops immediately. One bad result near the top makes the AI feel unserious.

Recommended fix:

- Add negative filters for sports searches: `구명조끼`, `수영조끼`, `팝업북`, `만들기`, `스티커`, `도서`, `DVD`, `금연`.
- Replace broad `조끼` matching with `팀조끼`, `띠조끼`, `게임용 조끼`, `체육 조끼`.

### P0. Popularity signal is contaminated

One Teachermall product reports `purchase_count: 2147485642`, likely an overflow/sentinel/data issue. It dominates popularity ranking.

Impact:

- "반응 좋은" results become distorted.
- The system over-trusts one product and makes rankings look suspicious.

Recommended fix:

- Clamp or winsorize purchase counts.
- Treat extreme values above a reasonable ceiling as missing or capped.
- Build separate normalized signals per mall because Teachermall purchase counts and i-Scream wish/review counts are not directly comparable.

### P1. Budget kit lacks category diversity

The generated 100만원 basket over-selects similar products. It picked many 피구공/플라잉디스크 variants and missed a balanced PE set with zones, team management, safety, warm-up, net/target games, and replacement supplies.

Impact:

- Budget is spent, but the basket does not feel like a curriculum-ready set.
- It does not answer "어떠한 활동에 사용 가능한가" deeply enough.

Recommended fix:

- Add category quotas:
  - 구기/던지기: 25-35%
  - 공간표시/코스: 10-20%
  - 팀구분/운영: 10-20%
  - 뉴스포츠/협동게임: 20-30%
  - 안전/운영 소모품: 5-10%
- Force at least one item from each required category when budget allows.
- Let the user choose class size and activity style.

### P1. Quantity logic is too mechanical

Quantity is currently based mostly on price bands. Cheap items default to 20, mid items to 8, expensive items to 1, then a fill loop keeps adding until the budget reaches 93%.

Impact:

- Quantities are not tied to class size, group count, or lesson design.
- The app may overbuy low-value or duplicate items simply to spend the budget.

Recommended fix:

- Ask or infer `students`, `groups`, `classes`, and `lessonMode`.
- Quantity formula should be product-category aware.
  - Team vests: one per student or team subset.
  - Balls: one per 4-6 students.
  - Cones/markers: one set per station or group.
  - Premium game sets: one or two per class.

### P1. UI does not show "why this was recommended"

Cards show price and purchase links, but not the reasoning behind selection.

Impact:

- The teacher sees products but not decision support.
- The core AI value is hidden.

Recommended fix:

- Add recommendation badges:
  - `학년 적합`
  - `안전성`
  - `협동 활동`
  - `반응 근거`
  - `예산 효율`
- Show one-line rationale and one concrete lesson use case per item.

### P1. The result flow is split between search and budget, not answer-first

Natural-language prompt users expect an answer. The current UI feels like it takes the prompt, fills controls, and shows product cards/cart. It does not produce a summarized purchase proposal first.

Recommended fix:

- Add an answer panel above results:
  - "추천 구성 요약"
  - "총액/잔액"
  - "왜 이 조합인가"
  - "수업 운영 시나리오 3개"
  - "구매 우선순위"

### P2. HWPX/PDF buttons are visible but disabled

Impact:

- Since the user explicitly wants document output, disabled buttons can feel unfinished.

Recommended fix:

- Either hide disabled exports until ready, or add a working HTML/Markdown report preview first.
- Next implementation should add a server-side `/api/report` that returns structured report JSON and Markdown.

### P2. Mall comparison is underdeveloped

The UI shows mall counts, but does not clearly explain when Teachermall is better, when i-Scream is better, or which substitute to choose.

Recommended fix:

- Add per-category mall comparison:
  - lowest price
  - stronger reaction signal
  - better category fit
  - same/similar product duplicate detection

## Recommended Build Plan

### Phase 1: Trust repair

1. Add negative filters and sport-specific match rules.
2. Clamp abnormal popularity counts.
3. Add category classification for products.
4. Add diversity quotas for budget kits.
5. Add class-size/group-size quantity rules.

### Phase 2: Real AI recommendation

1. After product retrieval, send candidates to Gemini.
2. Ask Gemini to return strict JSON:
   - selected items
   - rejected items
   - category coverage
   - quantities
   - teacher rationale
   - activity use cases
   - safety notes
3. Validate Gemini output against real candidate IDs only.
4. Fall back to deterministic ranking if Gemini fails.

### Phase 3: Teacher-ready report

1. Add report preview tab.
2. Generate Markdown from selected/AI-ranked items.
3. Add report sections:
   - purchase list
   - item comparison
   - activity plan
   - budget summary
   - links
4. Integrate HWPX after report JSON stabilizes.

## Suggested New API Shape

```text
POST /api/intent
POST /api/candidates
POST /api/recommend
POST /api/report
```

`/api/recommend` should be the main AI endpoint. It should accept:

```json
{
  "prompt": "6학년 체육교육에 100만원...",
  "intent": {},
  "candidates": []
}
```

It should return:

```json
{
  "summary": "...",
  "selected": [
    {
      "mall": "teachermall",
      "goods_seq": "1199418",
      "quantity": 6,
      "reason": "안전 피구와 협동 활동에 적합",
      "activities": ["팀 피구", "표적 맞히기", "역할 순환 게임"],
      "risks": ["공 크기 옵션 확인"]
    }
  ],
  "rejected": [
    {
      "goods_seq": "1065000",
      "reason": "구명조끼 팝업북으로 체육 교구 목적과 다름"
    }
  ]
}
```

## Bottom Line

The product should move from "AI-powered search controls" to "AI-curated purchase proposal." The first satisfaction jump will come from relevance cleanup and category-balanced budgets. The second jump will come from Gemini explaining and validating the final basket using real retrieved products only.
